# LOL 皮肤购买决策

数据全部来自用户本机英雄联盟客户端的只读接口（LCU），不上传、不改客户端。

## 工作目录

下面所有命令都在**项目根目录**执行（包含 `cli/lol.js` 的那一层）。如果当前目录是 skill 目录，先 `cd ../..`。需要 Windows + Node.js 18+ + 已登录的国服客户端；没有 Node 时改用桌面端的 `LOL皮肤决策助手.exe`。

## 前置检查

先跑一次状态检查，确认能连上：

```bash
node cli/lol.js status --json
```

返回 `{"connected": true, "summoner": {...}}` 就可以继续。

如果返回 `needsElevation: true`，说明客户端在跑但读不到凭据——CLI 会自动静默提权重跑，通常无需干预。若仍失败，提示用户双击解压目录里的 `LOL皮肤决策助手.exe`（右键以管理员身份运行）打开界面。

## 核心工作流

### 1. 从用户输入里提取皮肤清单

用户的输入可能是：

| 形态 | 处理方式 |
|---|---|
| **截图**（商城页、限时折扣页、皮肤列表） | 用视觉能力逐条读出「皮肤名 + 英雄名」，不要翻译、不要补全，照抄图上的文字 |
| **文本清单** | 直接逐行取，去掉序号/项目符号 |
| **只给了英雄名** | 先跑 `champion <championId>` 拿该英雄全部皮肤，再帮用户挑 |

提取时注意：
- 皮肤名通常是「活动名 + 英雄」两段（如「星之守护者 阿狸」），**整段保留**
- 图上如果有价格/折扣，一并记下来，用于后面交叉核对
- 拿不准的条目宁可保留原文让引擎去匹配，不要自己改写成"看起来对"的名字

### 2. 写清单并分析

把条目写进临时文件（一行一个），然后调用：

```bash
node cli/lol.js analyze --file <清单文件> --json
```

返回结构（关键字段）：

```jsonc
{
  "summary": { "matched": 5, "inputLines": 6, "unresolved": 1, "totalPrice": 21750, "hasPrice": true },
  "groups": {
    "S": [ { "skinName": "喵凯", "championName": "扭曲树精", "rarityLabel": "史诗",
             "price": { "rp": 8900, "originalRp": 8900, "discountPct": 0, "nonRp": false, "saleEnd": "..." },
             "usage": { "masteryLevel": 5, "masteryPoints": 22921, "games": 0, "rank": 107 },
             "owned": false, "reason": "..." } ],
    "A": [...], "B": [...], "C": [...], "D": [...], "skip": [...]
  },
  "unresolved": [ { "raw": "...", "reason": "..." } ]
}
```

### 3. 解读分档（不要自己重新排序）

| 档 | 含义 | 建议口径 |
|---|---|---|
| **S** | 该英雄一件皮肤都没有 | 最该补，优先推荐 |
| **A** | 皮肤等级高于该英雄已有最高档 | 明显升级，值得买 |
| **B** | 同档但当前折扣 ≥40% | 看折扣买 |
| **C** | 同档 | 收藏向，可选 |
| **D** | 低于已有最高档 | 不建议 |
| **skip** | 已拥有 | 明确告诉用户「这个你已经有了」，避免重复消费 |

同档内的顺序已经按**常用度**排好（成就等级 × 熟练度）。理由里带 `usage.masteryLevel` 的英雄就是用户常玩的。

### 4. 组织回答

建议结构：

1. **一句话结论**：先给 `S` 档和 `A` 档的 2~3 个名字
2. **分组清单**：每档列皮肤名、英雄、等级、价格/折扣、为什么（引用 `reason`，可口语化）
3. **避开坑**：`skip` 档要点名告诉用户哪些已经有了；`price.nonRp: true` 的标注「非点券直购（神话精萃/活动）」
4. **总价**：`summary.totalPrice`，如果用户给了点券余额可以对比
5. **未识别条目**：如实说明有几条没匹配上，请用户确认写法

不要编造价格。`price` 为 `null` 就说「没拿到价格」，不要估。

### 5. 可选：社区评价

如果用户想了解某款皮肤的手感/评价，可以联网搜索，例如：

```
<皮肤名> 皮肤 评价 手感
<皮肤名> skin review
```

搜索时注意：优先看 up 主实测、社区讨论，别把营销站当权威。给出结论时说明来源。

## 其他可用命令

```bash
# 藏品概览（英雄数、皮肤数、零皮肤英雄列表）
node cli/lol.js collection

# 常用英雄 Top 20（按成就等级与熟练度）
node cli/lol.js top --limit 20

# 单品详情（是否已拥有 + 价格）
node cli/lol.js skin 103014 --json

# 单英雄全部皮肤
node cli/lol.js champion 103 --json

# 每个英雄「上次在选人界面选的皮肤」（读客户端配置，不用进游戏）
node cli/lol.js prefs --json

# 当前选人阶段我锁定的英雄与皮肤（只有 BP 阶段能读到）
node cli/lol.js current --json
```

## 数据层的其他能力（界面里有，CLI 未直接暴露）

| 能力 | 说明 |
|---|---|
| 商城全集 | 1967 款：点券在售 832 / 非点券直购 1135 / 限定 378 / 限时销售 79 |
| 神话商店 | 走 itemshop.gg，国际服轮换（featured + biweekly），价格单位神话精萃 |
| 国服活动 | 从腾讯活动页解析，如「BLG 夺冠庆典」30 款神话半价 + 722 款点券半价，写在 `data/act-sale.json` |
| 皮肤上线时间 | 1822 款，`data/skin-release.json`，越新通常特效越好 |
| 人气榜 | Top 50，`data/popular-skins.json`，按 SkinSpotlights 播放量 |

需要这些数据时，让用户打开界面看，或者直接读 `data/` 下的 JSON。

## 已知边界（回答时要说清楚）

- **对局数据不参与推荐**：当前版本的常用度只按英雄成就等级与熟练度计算，成就数据对全部英雄完整。
- **经典模式英雄已被过滤**：客户端的藏品里有 88 个「Jade」变体（同名不同 id，或使用旧译名如「流浪法师」「审判天使」），工具已全部剔除，不会出现两个「暗裔剑魔」。
- **不代付**：只做推荐，购买由用户在客户端里完成。
- 客户端从「大厅」切到「对局中」时部分接口会短暂不可用，重试即可。
