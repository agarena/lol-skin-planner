## 0. 这份文档怎么用

### 0.1 文档分工

| 文件 | 回答什么问题 | 谁改 |
|---|---|---|
| `README.md` | 这是什么、怎么装、怎么用、数据从哪来 | 面向用户 |
| `DESIGN.md` | 长什么样、叫什么、用哪个组件 | 视觉唯一权威 |
| `docs/SPEC.md` | 有哪些界面/模块/元素、数据怎么流、口径与互斥 | 产品 + 开发 |
| `docs/TEST.md` | 每一步点哪里、应该看到什么、mock 还是真客户端 | 测试 |

修改功能时的顺序：**先改 SPEC → 再改代码 → 最后同步 TEST 与 DESIGN**。
编号只增不复用；删掉的功能保留编号并标注「已删除」，避免测试与历史记录错位。

### 0.2 编号规则

| 前缀 | 含义 | 示例 |
|---|---|---|
| `GL` | 全局框架（顶栏、底栏、全局状态） | `GL-01-03` |
| `SC-01`～`SC-07` | 七个界面 / 浮层 | `SC-02` 皮肤页 |
| 模块字母 | 界面内的功能块 | `SC-02-F` 筛选面板 |
| 元素编号 | 模块内的具体控件 | `SC-02-F01` 搜索框 |
| `D-A`～`D-F` | 数据章节的五张表 | `D-C` 数据关联 |

### 0.3 测试环境标记

| 标记 | 含义 |
|---|---|
| **M** | `?mock=1` 下可测（不连客户端） |
| **R** | 必须真实客户端 / 真实账号数据 |
| **E** | 需要专门构造异常（断网、改文件、旧版本分享码等） |

mock 入口：`http://127.0.0.1:5199/?mock=1`（开发态）或打包后的 `index.html?mock=1`。
mock 下 `window.lol = mockApi`，数据量为 168 英雄 / 2008 皮肤，仅用于看布局，**不代表真实口径**。

## GL-02 提权横幅

| 条件 | 表现 |
|---|---|
| `status.connected === false && status.needsElevation === true` | 顶栏下方黄色横幅：`⚠ {reason}` + 按钮「以管理员身份重启」 |

## GL-04 全局状态与反馈

| 状态 | 触发条件 | 表现 | 恢复 |
|---|---|---|---|
| 首次加载 | 应用启动、藏品未返回 | 页面内 LoadingState「正在读取数据」 | 数据返回自动消失 |
| 未连接 | `status.connected === false` | SC-01/SC-02 显示 NotConnected 卡：图标、标题、三步引导、刷新按钮、`status.reason` | 启动客户端后点刷新 |
| 需要提权 | 未连接且 `needsElevation` | NotConnected 换成锁图标 + 管理员重启按钮 | 提权重启 |
| 操作反馈 | 刷新成功/失败、复制、导入、缓存清空等 | 底部居中 toast，约 2.6 秒自动消失 | 自动 |
| 渲染异常 | 组件抛错 | ErrorBoundary 兜底页 | 重启窗口 |
| 单实例 | 重复启动 | 聚焦已有窗口，不开第二个 | — |

## GL-05 页面容器

- 三个页签**常驻挂载**，切 tab 只切换 `display`，因此筛选、滚动、输入内容在切页后保留。
- 主区高度 = 窗口 − 顶栏 − 底栏（有横幅时再减横幅）。
- 窗口默认 1360×880，最小 1040×680；无边框，顶栏自绘。

## GL-06 设置抽屉（SC-04）

右侧抽屉 + 半透明遮罩。点击遮罩或右上 × 关闭；**当前不支持 Esc 关闭**。

### SC-01-C 决策输入

| 编号 | 元素 | 作用 | 数据字段 | 空态 | 交互 |
|---|---|---|---|---|---|
| SC-01-C1 | 多行输入框 | 输入皮肤名清单，一行一个或用 `；` 分隔 | 本地 `text` | 占位文案说明可直接输入皮肤名 | `Enter` 发送（`Shift+Enter` 换行；中文输入法合成中不触发） |
| SC-01-C2 | 图片按钮 | 历史功能入口 | — | 固定禁用 | 点击提示「图片识别已移除，请直接输入皮肤名」 |
| SC-01-C3 | 发送按钮 | 进入 SC-05 确认 | `text` 非空且不在分析中 | 空白时禁用；分析中转圈 | 调 `skinParse` 解析；若是分享码则走 `importPlan` |
| SC-01-C4 | 提示条 | 解析反馈 | 本地 `imgNote` | 默认隐藏 | 显示失败原因/分享码问题，输入变化不自动清除 |

解析分支（重要）：

1. 文本含 `咕咕…嘎嘎` → 按分享码导入 → 用藏品建索引 → 打开确认弹窗；
2. 否则按皮肤名/英雄名模糊匹配 → 打开确认弹窗；
3. 一条都没匹配 → 提示「一个皮肤都没匹配上，检查下名字写法」。

### SC-05-C 分享口令

格式：`【方案名】口令 咕咕…嘎嘎[ 到期YYYY-MM-DD]`。

- 编码链路：皮肤 ID → 全量皮肤排序索引 → 相邻 delta → varint → DEFLATE → Base64url → 包裹符。

- 有包裹符但解码失败 → 报错，不降级成名字匹配；无包裹符 → 才走皮肤名模糊匹配。

## D-C 数据关联

```
skinId ──floor(/1000)──> championId
   │                        │
   │                        ├─> collection.champions[championId]（拥有、皮肤、最高档）
   │                        ├─> usage.byChampion[championId]（成就等级/点数）
   │                        ├─> stats.byChampion[championId]（排位/乱斗梯度）
   │                        └─> score 上下文（该英雄各稀有度已拥有数）
   │
   ├─> catalog.skins[skinId]（中文名/稀有度/系列/绝版/宇宙）
   ├─> storeItems[skinId]（价格/折扣/限时/在售/精品）
   ├─> loot.bySkinId[skinId]（碎片/永久 → 拥有状态）
   ├─> chromaMap[skinId]（炫彩/臻彩拥有数）
   ├─> release[skinId]（上线年月）
   ├─> popular[skinId]（人气排名，仅排序参考）
   └─> mythicSale[skinId]（神话半价活动）
```

| 关联 | 规则 | 影响界面 |
|---|---|---|
| 皮肤 → 英雄 | `Math.floor(skinId / 1000)` | 卡片副标题、英雄筛选、英雄浮层 |
| 英雄 → 成就 | `usage.byChampion[championId]` | 常玩英雄、成就筛选、荣耀分、排序 |
| 英雄 → 梯度 | `stats.byChampion[championId].ranked/aram.tier` | 卡片状态标签、梯度筛选、结果「英雄强度」 |
| 皮肤 → 商城 | `storeItems` 以 `skinId` 索引；商城字段覆盖藏品字段 | 价格、折扣、限时、精品、最新 |
| 皮肤 → 战利品 | `loot.bySkinId[skinId].permanent/shard` | 拥有状态四态 |
| 皮肤 → 方案 | `plan.skinIds[]`；方案只存 ID | 方案详情用**当前会话的藏品/商城快照**关联；商城快照进程内复用，客户端改价后需刷新页面/重启才更新 |
| 皮肤 → 分享码 | 全量非基础皮肤按 ID 排序后的位置 | 分享/导入 |
| 神话商店 → 本地 | `item:skin:131076` 取数字 → 本地中文名/拥有状态 | 神话看板 |
| 账号 → 缓存 | 藏品缓存按 `summonerId` 隔离 | 切换账号不会读到上一个账号藏品 |

## D-D 指标口径

| 指标 | 定义 | 注意 |
|---|---|---|
| 英雄总数 | 过滤经典模式后的英雄数（真实 173） | 原始接口 262，含 88 经典模式 + 1 占位 |
| 皮肤总数 | 全部英雄（含未拥有英雄）的非基础皮肤，剔除经典模式 ID 段（真实 1967） | 基础皮肤 `isBase` 不计 |
| 已拥有皮肤 | `ownership.owned` 或 `ownership.rental.rented` | **租借中的皮肤也计入拥有** |
| 已拥有英雄 | `championship.owned` | 不含经典模式 |
| 零皮肤英雄 | 已拥有英雄且 `ownedSkinCount === 0` | 不含未拥有英雄 |
| 无史诗及以上 | `maxOwnedRarityRank < 3` | 零皮肤英雄也满足 |
| 无传说及以上 | `maxOwnedRarityRank < 4` | 包含无史诗 |
| 稀有度 | `skins.json.rarity` → 8 档：普通/稀有/史诗/传说/神话/终极/卓越/圣堂 | 权重 1–8 |
| 限定 | `skins.json.isLegacy` | 不用商城 `tags.limited`（只有 5 条，不可靠） |
| 限时销售 | 在售且 `inactiveDate` 不是 2029/2099 占位 | 占位日期不算 |
| 限时打折 | `sale.percentOff > 0` | 与限时销售可同时成立 |
| 非点券直购 | 不在 LCU 点券商城（`inStore=false`）或没有 RP 价格 | 商城列表口径；比较/单品价格路径还会把 ≥50000 的占位价视为非直购 |
| 精品推荐 | `/lol-store/v1/featured` 中的 `CHAMPION_SKIN` | — |
| 常玩英雄 | 有成就记录的已拥有英雄，按 `masteryLevel × 1000 + masteryPoints / 100` 降序 | 不采集对局；`recent30` 恒为 0 |
| 梯度 T1–T5 | OP.GG `average_stats.tier`，1 最强 | 国服用 global 数据，非国服专属 |
| 上线年月 | 在售优先 `store.releaseDate`，否则 `data/skin-release.json` | 缺失显示「未知」 |
| 方案合计点券 | 各皮肤当前 `rp` 求和 | 非点券直购/已拥有不计入 |
| 推荐值 | 八项之和，见下 | 卡片与结果弹窗共用同一实现 |

推荐值八项：

| 项 | 规则 |
|---|---|
| 稀有度 | 基础分：普通 2 / 稀有 6 / 史诗 10 / 传说 18 / 终极 30 / 神话 100 / 卓越 300 / 圣堂 1000；减去该英雄所有已拥有皮肤各自档位 × 50% |
| 售价 | 原价 ÷ 100 |
| 限定 | +20 |
| 臻彩 | 每个 +100 |
| 炫彩 | 每个 +10 |
| 零皮肤 | 该英雄无皮肤 +100 |
| 荣耀 | 1–5 级 ×1，6–10 ×2，11–20 ×3，21–30 ×4，31+ ×5 |
| 新鲜度 | ≤2015 = 5；2016–2020 = 10；2021 起 15 + (年−2021) × 5 |

## D-E 互斥矩阵

图例：`单` = 组内单选；`多` = 组内多选；`⊥` = 互斥；`+` = 可叠加。

| 维度 | 取值 | 选择方式 | 与其他维度的关系 |
|---|---|---|---|
| 方案 `planId` | 无 / 方案 ID | 单 | ⊥ 快速视图、⊥ 商城视图；选中时 `view=all` |
| 视图 `view` | all / sale / limitedTime / mythic / featured / legacy / newest | 单（三组共用） | ⊥ 方案；三组之间互斥 |
| 只看未拥有 | 开/关 | 独立 | + 一切 |
| 零皮肤英雄 | 开/关 | 独立 | + 一切 |
| 无史诗及以上 | 开/关 | 独立 | + 一切 |
| 拥有状态 `state` | all / owned / none / lootShard / lootPermanent | 单 | + 其他 |
| 获取方式 `acquire` | all / inStore / notPurchasable / limitedTime | 单 | + 其他 |
| 活动折扣 `activity` | mythicSale / onSale | 多（OR） | + 其他 |
| 英雄 `championIds` | 多选 | 多（属于其一） | + 定位/梯度/成就段 |
| 定位 `roles` | 6 类 | 多 | + 英雄 |
| 梯度 `tiers` | T1–T5 | 多 | + 英雄 |
| 成就段 `masteryBand` | 全部 / lv10 / lv5 / lv0 | 单 | + 英雄 |
| 系列 `lines` | 多选 | 多 | + 其他 |
| 稀有度 `rarities` | 8 档 | 多 | + 限定 |
| 限定 `legacy` | 开/关 | 独立 | 与稀有度是 AND |
| 年份 `years` | 2020- / 各年（unknown 只计数，不可选） | 多 | + 其他 |
| 普通炫彩 `ownedChroma` | 开/关 | 独立 | + 其他 |
| 臻彩 `ownedPrestige` | 开/关 | 独立 | + 其他 |
| 排序 `groupMode` | 6 种 | 单 | 只影响分组，不影响筛选 |
| 卡片角标 | 已拥有丝带 / 折扣限时角标 | — | ⊥ 两者只能出现一个 |
| 卡片价格 | 已拥有 / 神话精萃 / 点券 / 非直购 | — | ⊥ 四态互斥 |

组合语义：**不同维度之间 AND；同一维度多选之间 OR**（英雄头像多选是「属于其一」，也是 OR）。

## D-G 非可视约束

| 约束 | 说明 |
|---|---|
| 只读 | 不注入、不改客户端文件、不代付；`npm run audit` 检查 |
| 管理员权限 | 国服 lockfile 常为 0 字节，凭据在进程命令行，普通权限读不到 |
| 提权方式 | PowerShell `Start-Process -Verb RunAs`，工作目录必须是 app 绝对路径（提权后 cwd 会变 System32） |
| 单实例 | `requestSingleInstanceLock()`，重复启动只聚焦 |
| 资源代理 | 自定义 `lcu://` 协议，主进程转发客户端图片；离线可用，缓存 24h |
| 目录过滤 | 5 层判据 + 同名保留最小 ID；`filterVersion` 变化使旧缓存失效 |
| 分享码依赖全集 | 皮肤总数变化会导致旧码无法还原；错误必须明示 |
| 账号隔离 | 藏品缓存按 `summonerId`；方案不按账号隔离 |
| 前端隔离 | 渲染进程只能通过 preload 白名单调用 IPC，不直接碰 LCU |
| 时间 | 界面按本地时区展示；方案 `createdAt/updatedAt` 存 ISO 字符串 |

## D-H 已知限制与风险

1. `plans.json` 直接覆盖写，写入过程中断电/崩溃可能留下损坏文件；读取失败会退回空列表，不会崩溃，但方案会「消失」。
2. CLI 的方案文件默认在临时目录，与桌面端 `userdata/plans.json` **不是同一份**。
3. 分组列表每个二级分组最多渲染 60 张卡片，「再显示 240 款」不会突破该上限。
4. 方案列表不区分账号：切换账号后仍能看到上一个账号创建的方案。
5. 神话商店依赖 itemshop.gg 联网；其条款要求展示时保留来源链接。
6. OP.GG 没有国服数据，梯度是 global 口径，只能作为参考。
7. 国服商城接口可能被运营后端接管，价格模块可能整体不可用。
8. 设置抽屉、删除确认、方案详情表不支持 Esc 关闭（其他弹层支持）。
